# Final Score Guard V7.2

Исправляет конкретный баг:
Мулти Милк имел Sales Score 84 при наличии только общего корпоративного email
и гендиректора без прямого телефона/email.

## Жёсткие правила теперь применяются дважды

1. В sales_scoring.py
2. Ещё раз в final_verification.py

Поэтому завышенный Sales Score не сможет пройти в финальную выдачу даже если
в Railway случайно осталась старая версия одного из модулей.

## Финальные caps

– нет ЛПР и нет способа связи → максимум 49;
– ЛПР известен, но связи нет → максимум 59;
– только общий корпоративный контакт → максимум 79;
– 90–100 → только конкретный ЛПР + его прямой телефон/email.

## Исправление стадии V

Если stage == V:
– land_status принудительно становится land_defined;
– Sales Score максимум 59.

Это убирает противоречие:
«V – участок определён» + «вероятно требуется участок».

## Заменить

app/services/sales_scoring.py
app/services/final_verification.py

Redeploy:
– zemlya-ai-agent
– zemlya-worker

Новых variables нет.

После следующего успешного запуска Мулти Милк из текущего примера должен быть
не выше 59 из-за стадии V, даже несмотря на корпоративный email.
